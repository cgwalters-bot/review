# review-service

> This text was generated by an LLM ([how cgwalters uses LLMs](https://github.com/cgwalters/cgwalters#llms)). cgwalters has not reviewed it yet.

A persistent service that builds the control plane's state from GitHub
queries rather than from JSON the pass stores in comments, and serves it
read-only with the review app. This is the first slice of review#281.

Every `--interval` seconds (default 60, 30 to 3600) it reads:

- **runs**: unfinished Actions runs of every tracker workflow (passes and
  the jobs they dispatch) and of the devspace `agent.yml`;
- **prs**: the bot's open PRs anywhere, each with GitHub's `mergeable_state`;
- **waiting**: open issues and PRs assigned to the operator or requesting
  his review, one entry per item with its reasons.

Run and PR reads are conditional on the last answer's ETag, so an unchanged
answer costs no rate budget; the three searches have no ETags and are what
bounds the interval (search allows 30 a minute). Each section says when it
was read, whether its list was whole (one page of 100 is read), and why its
last read failed, in which case it keeps the items it last read.

It serves:

- `GET /api/state`: the whole state (`review-service/v1`);
- `GET /api/repos/OWNER/REPO`: one repository's runs, PRs and waiting items;
- `GET /api/events`: server-sent events, a `state` event with the whole
  state on connecting and after each refresh;
- everything else from the built app (`--static`, default `dist`).

It has no route that writes, and its GitHub client sends only GETs.

## Running it locally

    npm run build
    GH_TOKEN=... cargo run --manifest-path service/Cargo.toml

and open http://127.0.0.1:8787. The token needs only read access; without
`GH_TOKEN` or `GITHUB_TOKEN` it uses `gh auth token`. It listens on
loopback by default: anyone who can reach it reads what the token can, so
put it behind authentication before giving `--listen` another address.
It refuses requests whose `Host` is a domain name other than `localhost`,
so a web page can't read the state by pointing its own name at 127.0.0.1
(DNS rebinding).

The app doesn't read from the service yet, nor does the service read pools,
pace or the pass's decisions (from the pass's run summary); those are
follow-up slices.

`cargo test --manifest-path service/Cargo.toml` checks the state model
against the answers in `fixtures/github.json`, the conditional requests
against a local fake GitHub, and the endpoints and events.
